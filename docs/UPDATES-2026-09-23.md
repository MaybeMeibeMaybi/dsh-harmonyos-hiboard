## 一、架构演进总览

### 改动前

```
手机 ──► 阿里云:18080 (frps) ──► 反向隧道 ──► 电脑 frpc ──► 代理:18080 ──► dsh:3080
手机 ──► 局域网:3081 ──► 入口代理 ──► dsh:3080
dsh 结果 ──► 华为 HIBoard ──► 负一屏卡片
```

公网暴露 **3 个端口**（22 / 7000 / 18080），且"手机 → 服务器"这一跳是**明文 HTTP**。

### 改动后

```
① 局域网：手机 ──► 电脑:3081 ──► 入口代理 ──► dsh:3080
② SSH 隧道：手机 ──ssh -L──► 服务器:22 ──隧道──► 电脑:18080 ──► dsh:3080
③ HTTPS 网关：手机 ──https:18443──► 服务器网关(密码) ──► 127.0.0.1:18080 ──► dsh:3080
dsh 启动 ──► ① 推 token 卡片到负一屏  ② 用注册密钥把 token 上报网关
```

公网暴露降为 **2 个端口**（22 仅密钥 + 18443 HTTPS+密码），**frp 整体退役**。

## 四、五个实测结论（都是踩坑得来的）

### 1. dsh 会话 cookie 按 authority 命名 —— 代理不能直接透传

`cookieName(authority) = 前缀 + sha256(authority)`。网关把 `Host` 改写成 `127.0.0.1:18080` 后，
dsh 下发的 cookie 是给该 authority 的；若原样透传给浏览器，浏览器会把它存到公网 IP 名下，
**后续请求带不回去**，表现为"第一次进入提示 `authentication required`"。

**正确做法**：网关自己持有 dsh 会话，浏览器只持有网关会话；网关在转发时注入 dsh cookie
并**剥掉上游的 `set-cookie`**。附带好处：dsh token 与 dsh cookie 都不进浏览器。

### 2. 用脚本手工传 cookie 测代理，会掩盖真实缺陷

第一版测试是"登录后手工把 dsh cookie 塞进请求头"，于是完全绕过了上面的问题。
改为**严格模拟浏览器**（cookie jar + 跟随重定向 + 只带自己手里的 cookie）后才复现。

**教训**：验证代理/网关这类组件，必须模拟真实客户端的凭据流转，而不是替它持有凭据。

### 3. schemastery 的 `.default()` 不会随 `{...Config}` 展开生效

`Config` 是 schema 对象，`{...Config}` 只能拿到 schema 自身的可枚举属性，
拿不到 `.default()` 填充的值 → 配置项变成 `undefined` → 请求 URL 为空。

**做法**：默认值写成独立常量（`DEFAULTS`），在 `apply()` 里显式兜底。

### 4. HIBoard 接口要求 `x-trace-id` 请求头

缺了会返回 `{"code":"0000500001","desc":"Parameter x-trace-id is empty"}`。
格式：`task-push-<yyyyMMddHHmmss>`。这与既有文档中的错误码表一致，现在有了实证。

### 5. 按命令行匹配杀进程，会误杀"承载这条命令的进程自己"

两次踩到：`stop-dsh.cmd` 里的一次性全杀 `powershell.exe`（会杀掉 harness 自身），
以及按 `dsh-auth-gateway` 匹配时匹配到正在执行该命令的 node 进程。

**做法**：所有进程匹配都加排除条件 `-notlike '*subprocess-local*'` 与 `'*runner.js*'`，
并且**永远不要**用 `taskkill /IM powershell.exe` 这类无过滤全杀。

## 五、Windows 脚本编码铁律（再次确认）

| 文件类型 | 要求 | 原因 |
|---|---|---|
| `.cmd` / `.bat` | **必须纯 ASCII** | cmd.exe 用系统 ANSI 代码页解码；UTF-8 中文会变乱码并**吃掉行首 `REM`**，乱码被当命令执行 |
| `.ps1` | 纯 ASCII，**或** UTF-8 **带 BOM** | PowerShell 5.1 无 BOM 时按 ANSI 解码，中文注释会让字符串终止符失效、解析失败 |

自检命令（两个数都应为 0；`.ps1` 若非 0 则必须带 BOM）：

```powershell
$raw = [IO.File]::ReadAllText('<file>'); ([regex]::Matches($raw,'[^\x00-\x7F]')).Count
```

## 六、部署顺序

1. **负一屏推送**（`dsh-harmonyos-hiboard`）：插件 + 卡片规则
2. **局域网访问**（`dsh-lan-remote-access`）：入口代理 + 启动器 + 入口插件
3. **公网中继**（`dsh-aliyun-relay-access`）：
   ① frp 起步 → ② 切 SSH 隧道并加固 → ③ 部署 HTTPS 网关 + CA
   ④ 配置 token 自动上报（免粘贴）

> 第 3 步的第 ③④ 项让手机侧退化为"只需浏览器 + 一次密码"，
> 这也是原生鸿蒙（无 SSH 客户端）唯一可行的方案。

## 七、已知限制

| 限制 | 说明 |
|---|---|
| **电脑必须开机** | 三条路径的 dsh 与入口代理都跑在电脑上；关机即三路全断 |
| 自签证书 | 需在手机安装 CA 才能消除浏览器警告（安装 CA 后完全正常） |
| 网关重启需重新输密码 | 网关的签名密钥每次启动随机生成，旧会话失效 |
| dsh 重启换 token | 插件会自动上报，浏览器静默重建会话；若插件未及上报，则回退到手工粘贴 |
| 免费额度 | 云服务器试用到期会释放实例，迁移见 `MIGRATION.md` |
| 仅手机端验证 | 未验证平板 / 折叠屏 / 手表等形态 |
| 浏览器版本 | dsh 客户端用到 `Iterator` helpers 与 `structuredClone`，需 **Chrome 122+ / Firefox 131+**；旧浏览器（含卓易通内旧版）会报 `Iterator is not defined` |
