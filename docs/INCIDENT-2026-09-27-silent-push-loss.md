# 事故复盘：推送"静默丢失"三连 × 一次宿主崩溃（2026-09-27）

> 这是一次**真实事故**的完整记录：两台机器上、同一晚，连着 3 张卡片没有出现在手机上，
> 而 dsh 界面**没有任何报错**。这份文档的目的是：让"推送没到"这件事从此**可观测、可归因、可兜底**。
>
> 所有站点相关的具体地址已替换为占位符（`<LAN-IP>` / `<GATEWAY-HOST>`），
> 授权码、密钥、私网/公网 IP 一律不入库。

---

## 一、结论先说

| 现象 | 真正原因 | 为什么难发现 |
|---|---|---|
| 卡片没到手机 | agent 把推送**写成了纯文本**，工具从未执行 | 那一轮 `turn/end` 是 `completed`，**零报错** |
| 又一张卡片没到 | agent 在正文里**承诺了推送**（"我把结论推给你："）却**根本没写调用** | 同上，承诺本身就是唯一的"证据" |
| 第三张卡片内容为空 | 解析器被 `<parameter name="content" string="true">` 的**额外属性**打败 | 解析失败被当成"参数不全"，安静地放弃 |
| dsh 进程崩溃 | 运行期间改写**被 HMR 监视的实跑文件** | `patchReload: live` 会热重载，且没留下堆栈 |

**共同点：全部是静默失败。** 用户是靠"手机上少了一张卡片"发现的，这不可接受。

---

## 二、三种失败形态（可直接拿去写测试）

### 形态 A：把调用写成了正文

assistant 消息的 `content` 里只有 `reasoning` + `text` 两块，`text` 结尾是这样的 XML：

```
测试完成，结论明确。我把评估推给你：

<hiboard_push>
<parameter name="content">## 结论 ...</parameter>
<parameter name="name">某方案评估</parameter>
<parameter name="result">已完成</parameter>
<parameter name="schedule_id">dsh_worklog</parameter>
</hiboard_push>
```

`content` 里**没有 `tool-call` 块** → 工具没跑 → HIBoard 从未收到请求。

### 形态 B：承诺了，但没调用

```
实测完成，我把结论和剩余验证清单推给你：
（正文……）
```

正文里既没有工具调用、也没有 XML 标记，只有一句"推给你"。**这是最隐蔽的一种**：
从会话记录里看，一切都正常。

### 形态 C：参数标签带了额外属性

```
<parameter name="content" string="true">## 手机端已成立 ...
```

第一版解析器用的正则要求 `<parameter name="k">` 后面**紧跟 `>`**，
遇到 `string="true"` 就匹配不上 → 只抓到 `name`/`result`，`content` 为空 →
被判为"参数不全"→ **放弃兜底**。

> 教训：宽松解析必须用**真实事故数据**做回归。人造样例永远是"干净的"。

## 三、修复：三级兜底（`dsh-push-guard`）

| 级别 | 触发条件 | 行为 |
|---|---|---|
| **L1 rescue** | 正文里出现字面量调用标记，且**该轮**从未真正调用 `hiboard_push` | 用同一个解析器还原参数，**按原样**代为推送 |
| **L2 promise** | 该轮未推送，但正文**明确承诺了推送**，且正文够长 | 用该轮正文补推，`result` 标注"模型未调用推送工具"，名字取正文标题 |
| **L3 retry** | `hiboard_push` 真的调用了但返回失败 | **按错误类别**重试：瞬时错误重试，永久错误（如授权码无效）不重试 |

判定"这一轮推过没有"用的是**轮次号**，不是消息序号 ——
否则"上一轮推过"会被误当成"本轮推过"，把兜底整个吃掉（v1 就是这么错的）。

### L2 的意图识别（保守优先）

命中条件（满足其一）：

- 出现"**推/发/送给(你)**"这类明确短语（`我把结论推给你：`）；
- 出现"**推送**"这个完整词；
- 推送动作词 + 目的地词（负一屏/卡片/手机/助手…）**同句**出现。

同句含否定/疑问/条件词则**不命中**：`要不要我把结果推给你？`、`我不会推送这张卡片。` 都不会误触发。
宁可漏判（少补一张），也不要误判（把普通聊天刷成卡片）。

### 可观测性（这才是"彻底修好"的关键）

```
<DSH_HOME>/lan/push-guard/
├── startup.json      启动自检：authCode 是否配置、三级开关状态、pid
├── last-state.json   最近一次兜底推送的结果（哪一轮、哪一级、成功与否）
└── audit.jsonl       审计流水：push-ok / push-failed / retry-ok / rescue-ok / no-push
```

外加一个自检工具 **`hiboard_push_selfcheck`**，一条命令回答四个问题：

```
push-guard 生效: ✅
hiboard_push 已被接管（失败重试）: ✅
authCode: 已配置
接口可达: ✅
最后状态: {...last-state.json...}
```

在这套东西之前，"保险丝到底有没有生效"只能靠猜 —— 本次事故里就真的猜错过一次
（测试进程写的状态文件被误读成"插件已在 dsh 里生效"，其实 dsh 里根本没跑）。

## 四、崩溃那一半：不要改正在被 HMR 监视的文件

读 `dsh-app-boot` 源码确认：profile 的 `patchReload: "live"` 会启动 Cordis HMR，
**监视 patch 文件（以及被加载的插件模块），一保存就热重载**。

事故当晚的操作序列是：改插件实跑副本 → `pnpm add` 重写 `package.json`/lock →
再改插件实跑副本 → 改 `cordis.patch.yml`，随后进程死亡（无堆栈）。

### 由此定的规矩

1. **改插件源码前先停 dsh**（HMR 也在盯这些文件）。
2. 新插件代码先 **staged**（`*.v2-staged.js`），等 dsh 停了再同步到实跑位置。
3. 改 `cordis.patch.yml` 必须**先备份**，改完**立刻验证**进程存活 + 端口仍在监听。
4. **同名 `insert` 条目只认第一个**：v1 与 v2 并存过一次，导致 v2 配置被静默忽略。
5. PowerShell 5.1 没有 `utf8NoBOM`：写 UTF-8 无 BOM 要用
   `[System.IO.File]::AppendAllText($p,$s,(New-Object System.Text.UTF8Encoding($false)))`；
   **绝不能用 `Add-Content -Encoding UTF8`**（会在文件中间插入 BOM，破坏 YAML 首行）。

## 五、验证用例（全部用真实事故数据回归）

| 用例 | 期望 | 实测 |
|---|---|---|
| 形态 A 真实正文 | L1 代为推送，参数逐字还原 | ✅ 正文 1799 字 |
| 形态 C 真实正文（带 `string` 属性） | L1 代为推送 | ✅ 正文 2230 字 |
| 形态 B 承诺句 + 长正文 | L2 补推，且正文里承诺句被去掉 | ✅ 卡片名取正文标题 |
| 该轮真的调用过工具 | 不重复推 | ✅ |
| 上一轮推过、本轮只有承诺 | 必须兜底（**轮次号**判定） | ✅ |
| 普通短回答 | 不推 | ✅ |
| `要不要我把结果推给你？` | 不命中（疑问句） | ✅ |
| `我不会推送这张卡片。` | 不命中（否定句） | ✅ |
| 授权码无效 `0000900034` | 判为永久错误，**不重试** | ✅ |
| 网络超时 | 判为可重试，重试 1 次 | ✅ 真实 HTTP 2 次 |

## 六、还能更进一步的地方（诚实标注）

1. **L2 依赖"承诺句"这一线索**。若模型既没承诺、也没写调用、也没调用工具，
   本轮就不会有卡片 —— 审计里会留下 `no-push` 记录，但**不会自动补**。
   这是刻意的：把每一轮都自动推成卡片会刷屏。
2. **没有端到端回执**。HIBoard 接口只回 `{"code":"0000000000"}`，
   无法确认"卡片真的渲染在手机上了"。因此"成功"的定义是**接口接受**。
3. **L1/L2 的卡片 `result` 会明确标注是兜底推的**，方便和模型亲自推的区分开。
