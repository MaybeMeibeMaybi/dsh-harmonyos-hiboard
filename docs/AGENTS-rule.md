# 让「每一轮回答都推送」对所有会话生效

`hiboard_push` 是一个**工具**，工具本身不会自动调用——需要有一条**常驻指令**告诉 agent
什么时候调用。dsh 提供了干净的做法：**全局用户指令文件**。

---

## 做法：写 `~/.dsh/AGENTS.md`

dsh 由 `dsh-agent-instructions` 组件在**每个会话**（新老对话、所有 profile）自动加载
`$DSH_HOME/AGENTS.md`，把它注入系统提示。因此只要把规则写在里面，就是全局生效。

```markdown
# dsh 全局指令

## 强制要求：每轮回答都必须推送到手机负一屏

1. 每轮给出最终回答时，调用 `hiboard_push` 推送该轮的详细结论。
2. 卡片内容：
   - `name`：本轮任务名
   - `content`：详细结论，Markdown，**上限 5000 字符**；超长时推精简版并注明被截断
   - `result`：状态摘要（默认「任务已完成」）
   - `schedule_id`：**必须传**，否则卡片不显示正文（用固定值如 `dsh_worklog` 可分组）
3. 即使本轮无实质输出，也推一张简短卡片，不要跳过。
4. 推送失败时必须写明原因（工具不可用 / 未配置 authCode），不要静默略过。
```

---

## 已知边界（务必如实告知，不要假装成功）

- `hiboard_push` / `hiboard_verify` 由插件注册，**只在装了该插件的 profile 中存在**。
  本项目按 `web` profile 部署；在 `headless` / `tui` 等 profile 中**没有**这个工具，
  因此无法推送。
- 授权码配置在 `~/.dsh/profiles/web/cordis.patch.yml`，**不要**放 `.env`（见 `DEPLOY.md` 第 3 步）。

---

## 跨机迁移提醒

换电脑时，除了本项目的插件，**也要把 `AGENTS.md` 一起拷过去**（或把上面的规则块重新写一份）。
否则功能在、但没人调用它。

验证方法：新开一个会话，问它"你每轮回答要做什么"，若系统提示已注入，它会答出推送要求。
