## 1. 修复（重要）：每张卡片实际推了两遍

### 症状

每次调用 `hiboard_push`，用户手机上会出现**两张**内容相同的卡片。

### 根因

`push-guard` 的 L3 包装器会重试"可重试的失败"。但它判断成功用的是 `classifyPush(outcome)`，
而 `outcome` 是 **`hiboard_push` 工具 `execute` 的返回值**：

```js
{ success: true, code: "0000000000", message: "OK", taskName, pushedAt, dryRun }
```

它**没有 `ok` 字段、没有 `body`、也没有 `status`**。而当时的 `classifyPush` 第一条就是：

```js
if (result.ok) { ...判断成功... }        // ← 工具返回值永远进不来
const permanent = PERMANENT_CODES.has(code) || (result.status >= 400 && result.status < 500);
return { ok: false, retryable: !permanent, ... };   // ← 于是每次成功都掉到这里
```

`code` 取自 `result.body`（不存在 → `""`），`status` 也不存在 → 判定为"**可重试失败**"
→ 包装器 sleep 后**再推一次** → 第二次 `next.success === true` → 记一条 `retry-ok` 返回。
两次推送的 `msgId` 不同（每次调用都新建），平台按 `msgId` 去重 → 用户看到两张。

### 证据

`~/.dsh/lan/push-guard/audit.jsonl`：

| 记录类型 | 条数 |
|---|---|
| `retry-ok` | **74** |
| `push-ok` | **0** |

首推若被判成功，包装器会记 `push-ok`；**一条都没有**，说明 74 次推送里首推**从来没有**被认成成功。
（第一次统计时用 `ConvertFrom-Json` 逐行解析，因编码问题有 56 行解析失败，得出 27 这个偏小的数字；
按 `"kind":"retry-ok"` 正则重数才是准的：**74 / 0**。）

### 修法

1. `classifyPush` 先单独认出"工具返回值"这个形状（`result.ok === undefined && typeof result.success === "boolean"`），
   直接按 `success` 判定成功/失败；
2. `sendPush` 与两个工具的返回值把 HTTP **`status`** 透传出来（`status: 0` = 超时/网络错误，没拿到响应），
   `pushOutputSchema` 同步加字段。

第 2 条是必需的：没有它，404（ELB 坏窗口）与 405（用错方法）在工具路径上根本无法区分 ——
也就是说第 3 节那个"404 当可重试"的修复**此前在工具路径上是空转的**。

### 影响

- 修前：**每次推送 2 张卡片**；修后：1 张。
- 修前：`0000900034`（授权码无效）这类永久错误也会被重试；修后不再重试。

## 2. 安全：公开仓库 `publish.ps1` 里的真实 authCode

### 问题

`publish.ps1` 的"发布前凭据扫描"把针脚写成**拼接字符串**：

```powershell
$needles = @(
    ('eh5Q6' + 'HVUFCDU'),        # 两半拼起来 = 完整 12 位 authCode
    ('2f655bdf' + 'c62e92ade')
)
```

- 拼接结果**等于**当时 `~/.dsh/profiles/web/cordis.patch.yml` 里的真值；
- 该端点**只靠请求体里的 `authCode` 鉴权**，拿到就能往用户负一屏推任意卡片；
- 注释说"本脚本不含它要搜的明文凭据"—— 但切成 5+7 一个字都没少；
- **项目自带的隐私扫描器也抓不到**：`scan-privacy.mjs` 是**连续原文精确匹配**，
  `'eh5Q6' + 'HVUFCDU'` 中间夹着引号和 `+`，所以 0 命中（已实跑验证）。

### 修法

- `publish.ps1` 不再保存任何凭据：新增 `-SecretsPath`（默认 `.\privacy-secrets.local.json`），
  从**仓库之外/被 gitignore 的本地 JSON** 读取真实值做比对；
- 取哪些键有明确白名单（`$CredentialKeys`），刻意排除 `userName` / `email` / `sshAlias`
  这类**本来就该出现在 LICENSE / NOTICE / 文档里**的值，否则每次发布都会被误拦；
- 命中时**只打印 `文件:行号 [键名]`，绝不回显凭据值**（旧实现在这一行也会把密钥打到控制台）；
- 文件缺失 → **fail closed**（退出码 1，除非显式 `-SkipSecretScan`）；
- 新增步骤 2b：若 secrets 文件在仓库内，用 `git check-ignore` **强制确认它被 gitignore**，
  否则拒绝发布；在仓库外则直接放行；
- `.gitignore` 增加 `privacy-secrets.local.json` 与 `*secrets*.local.json`。

### 配套：旋转 authCode

泄露的那个 authCode 已经**失效**（实测返回 `0000900034`），本机配置已换成新码；
`~/.dsh/profiles/web/cordis.patch.yml` 里三处 `authCode`（hiboard-push / token-broadcast / push-guard）已同步更新。

> 注意：旧码仍在公开仓库的 **git 历史**里（删除文件不影响历史）。因为**旋转已经完成**，
> 历史里那枚码已经无用；若还想彻底抹掉，需要改写历史（filter-repo/BFG）并强推。

## 3. `push-guard`：重试预算拆成两份

新增配置 `ambiguousRetryCount`（默认 **1**），与原有 `retryCount`（默认 3）分工：

| 失败类别 | 含义 | 用哪份预算 |
|---|---|---|
| ELB 直出的 **404** | 请求**确定**没进业务服务 | `retryCount`（默认 3，配指数退避） |
| 超时 / 无响应 / 5xx / 业务侧未知失败码 | **可能已经送达**，只是响应丢了 | `ambiguousRetryCount`（默认 1） |
| `0000900034` / 405 等 | 永久错误 | 都不重试 |

理由：每次重试都会重新构造负载、生成**新的 `msgId`**，而平台按 `msgId` 去重 ——
对"可能已送达"的失败多试几次，代价就是用户手机上多出重复卡片。

`startup.json` / 启动日志 / `hiboard_push_selfcheck` 都会打印这两份预算与当前卡片来源，便于事后核对。

## 4. 卡片来源（`source`）可配置

负一屏卡片上那个**来源 / AI 工具名**由负载的 `source` 字段决定（平台按它做品牌化渲染）。

- 三个插件都新增 `source` 配置项，**默认仍是 `"OpenClaw"`**，与原行为、官方 `today-task` skill 一致；
- 实测：自定义值（如 `DeepSeek Harness`）同样返回 `0000000000`，**平台接受**；
  但渲染样式由平台决定，换值后请先在真机上看一眼；
- 涉及：`src/lib/index.js`（`hiboard_push`）、`src/push-guard/lib/index.js`（L1/L2 兜底卡片），
  以及私有仓库 `dsh-hiboard-startup-card` 的启动卡片；
- `User-Agent` 保持 `OpenClaw-TaskPusher/2.0` 不变 —— 它不显示在卡片上，属于传输层兼容值。

配置示例（`~/.dsh/profiles/web/cordis.patch.yml`）：

```yaml
- id: hiboard-push
  config:
    authCode: <AUTH-CODE>
    source: 'DeepSeek Harness'      # 卡片上的来源名；省略即 OpenClaw
```
