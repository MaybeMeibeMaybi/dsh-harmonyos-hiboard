## 1. 新增：`src/push-guard/` — 推送兜底插件

三级兜底 + 自检 + 审计，全部由宿主侧完成，不依赖模型"记得调用工具"。

| 级别 | 触发条件 | 行为 |
|---|---|---|
| **L1 rescue** | 正文出现字面量调用标记（`<hiboard_push><parameter …>`），且**该轮**从未真正调用工具 | 用同一解析器还原参数，按原样代为推送 |
| **L2 promise** | 该轮未推送，但正文**明确承诺了推送**（"我把结论推给你："）且正文够长 | 用该轮正文补推；`result` 标注"模型未调用推送工具" |
| **L3 retry** | 工具真调用了但返回失败 | 按错误类别重试：瞬时错误重试，永久错误（如 `0000900034`）不重试 |

### 实现上值得记下来的点（都是踩出来的）

1. **判定"本轮推过没有"必须用轮次号**，不能用消息序号 ——
   否则"上一轮推过"会被当成"本轮推过"，把兜底整个吃掉（v1 的真实 bug）。
2. **解析 `<parameter>` 的正则必须允许额外属性**（`[^>]*>`）。
   事故正文里写的是 `<parameter name="content" string="true">`，
   朴素正则匹配不到 `content`，会被误判为"参数不全"而**安静地放弃兜底**。
3. **L2 的意图识别要保守**：必须"动作词+给/到"或"推送"整词或"动作词+目的地词"，
   且同句不含否定/疑问/条件词。实测 `要不要我把结果推给你？`、`我不会推送这张卡片。`
   都不会误触发。
4. **兜底代码绝不允许拖垮宿主**：每个回调整体 try/catch，磁盘写入失败只记日志，
   审计日志有大小上限（写满滚动截断）。

## 2. 新增：可观测性（"彻底修好"的关键）

```
<DSH_HOME>/lan/push-guard/
├── startup.json      启动自检：authCode 是否配置、三级开关状态、pid
├── last-state.json   最近一次兜底推送（哪一轮、哪一级、成功与否）
└── audit.jsonl       流水：push-ok / push-failed / retry-ok / rescue-ok / no-push
```

并新增自检工具 **`hiboard_push_selfcheck`**：一条命令回答
"兜底插件生效了吗 / `hiboard_push` 被接管了吗 / 授权码配了吗 / 接口通不通 / 上次推的是什么"。

> 为什么需要它：本次事故排查中，曾把**测试进程**写的状态文件误读成
> "插件已在 dsh 里生效"（其实 dsh 里根本没加载）。没有自检就只能靠猜。

## 3. 修复：`src/token-broadcast/` 的 token 卡片

1. **地址不再是占位符**：原来卡片正文写的是 `https://<服务器IP>:18443/?token=…`，
   手机上无法使用。现在网关主机从 `registerUrl` 推导（可用 `gatewayHost` 覆盖），
   局域网 IP **每次启动动态探测**（实测同一天内就从 `192.168.0.x` 段换到了 `192.168.3.x` 段，
   写死必然过期）。
2. **不再推送失效的旧 token**：`web-state.json` 在 dsh 退出时不会被删除，
   上一轮 token 会一直躺在里面。现在校验文件里的 `pid` / `startedAt` 是否属于**本次运行**，
   只有确认新鲜才推 —— 推一张失效 token 比不推更糟。
