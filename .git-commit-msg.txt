fix!: hiboard_push_selfcheck made every request fail

0.9.0 registered the self-check tool for the first time, and that un-masked a worse
latent bug: its `parameters` was `{}`, which has no type, and dsh passes parameters
straight through to the model API without validating them locally. The API rejected
EVERY request:

    Invalid schema for function 'hiboard_push_selfcheck':
    schema must be a JSON Schema of 'type: "object"', got 'type: null'.

so the machine could not hold a conversation at all. Diagnosis came from the dsh on
the other machine; its PowerShell patch identified the causal chain (0.8.0 never
registered the tool, so the bad parameters had never been sent).

- `parameters` is now an explicit object-root schema.
- Both schemas moved to `src/lib/tool-schemas.js`, a dependency-free module, so
  `test/tool-schemas.test.mjs` can assert them from inside the repo. Nothing locally
  watched `parameters`: `assertSupportedJsonSchema` accepts `{}`, only
  `assertObjectJsonSchema` rejects it, and `register()` never calls the latter.
- `index.js` now validates every registered tool's `parameters` at load, logs an
  error, and echoes `toolSchemas:{ok,bad}` in the settings route. This class of
  failure can no longer ship silently.
- Card: the push-source hint is the shorter requested sentence.
- `buildConfigRoute` was missing the new `toolSchemaReport` parameter, which made
  `summary()` throw; caught by the verification harness before release.

Verified against the real dsh-tools validators, including negative controls.
